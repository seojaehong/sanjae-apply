# 안내 페이지 디자인 (261028)

`https://sanjae-apply.vercel.app/` 의 정본 설계. 화면을 고칠 때 이 문서부터 고친다.

## 누구에게 무엇을

- 읽는 사람: 산재 신청을 준비하는 재해자·가족, 신청을 돕는 사무소 직원, AI 도구에 MCP 를 붙이려는 사람.
- (261028 개편) 제품 소개 페이지 형식으로 바꿨다. 첫 화면의 일: **무엇을 해 주는지 한 줄 + 설치 한 줄(복사)**. 오른쪽에 채운 요양급여신청서 견본을 HTML 로 그리고, 서명란에 패키지가 만든 도장 그림(`public/img/seal_hong.png`, `cli seal --name 홍길동` 출력)을 찍는다.
- 순서: 첫 화면 → 작동 방식(연결 → 대화 → 저장, 실제 순서라 번호) + 예시 대화 → 특징 4가지 → 신청 전 확인표(`#try`, 브라우저 엔진) → 서식 표 → 사용 매뉴얼(`#manual`, 차례 + 연결 탭 5개) → 사용 확인(`#verified`) → 하지 않는 일 → 자주 묻는 질문 → 마무리 띠 → 바닥줄.
- 확인표 엔진은 npm 패키지와 같은 `src/core` 를 브라우저용으로 묶은 것이다. 입력값은 서버로 가지 않는다. `web/main.ts` 가 잡는 id(`#sheet`·`#result`·`#seal`·`#result-status`·`#cli-line`·`#fillable-data`)는 그대로 둔다. `#forms-body` 와 `data-version`·`data-form-count`·`data-total-slots`·`data-stamp-forms` 자리는 `scripts/build_web_data.mjs` 가 빌드 때 `public/index.html` 에 굽는다(JS 없이도 맞는 값이 보인다).

## 레퍼런스

design-md 의 `ibm`(Carbon) 을 **구조로만** 빌렸다. 공공·기관 서식 화면에 맞는 이유는 셋이다. 모서리 0px, 그림자 없이 1px 선과 바탕색 차이로 위계를 만든다, 4px 격자. 정체성은 빌리지 않았다. 글꼴(Plex)·고유 파랑(#0f62fe)·밝은 300 굵기 제목은 쓰지 않는다. 근로복지공단의 색·로고도 쓰지 않는다(기관 사칭 금지).

## 개념: 서식 용지

산재 신청은 종이 서식의 일이다. 그래서 페이지 자체를 **신청 전 확인표**라는 서식 한 장으로 만든다.

- 서식의 인쇄된 부분(칸 이름·선)은 먹색, **사람이 채운 값은 볼펜 파랑**으로 쓴다. 엔진이 돌려준 결과도 볼펜 파랑이다.
- 결과 상태는 **인주 도장**으로 찍는다. 「확인할 것이 남음」·「제출할 수 있는 상태」 두 가지뿐이다. 승인 여부는 다루지 않는다.
- 도장이 이 페이지에서 유일하게 대담한 요소다. 나머지는 조용하게 둔다.

## 배치

```
┌ 머리줄: (서식 칸 표지) 산재 신청 도우미   작동 방식 · 서식 N종 · 매뉴얼 · 사용 확인 · 자주 묻는 질문 [설치하기] ┐
│ 첫 화면: 제목(명조 46) + 설명 + 설치 한 줄(복사) + [설치 없이 필요 서식 확인하기]  │ 책상(--desk) 위 견본 서식 + 도장 │
├ 작동 방식 1·2·3 + 예시 대화                                                            │
├ 특징 4가지(도장 그림 포함)                                                              │
├ 신청 전 확인표(#try)  ┌ 확인표 ┬ 확인 결과(도장 · 서식 · 첨부 □/■ 준비함 · 남은 질문 · 명령줄 한 줄) ┐ │
├ 채울 수 있는 서식 N종 표(#forms, 빌드가 굽는다)                                         │
├ 사용 매뉴얼(#manual) · 사용 확인(#verified) · 하지 않는 일 · 자주 묻는 질문             │
└ 마무리 띠(어두운 바탕) · 바닥줄: 버전 · MIT · GitHub · npm                              ┘
```

- 왼쪽 정렬, 최대 폭 1120px. 휴대폰에서는 확인표 → 결과 순으로 세로로 쌓는다.
- 움직임은 둘이다. 첫 화면 견본의 도장이 한 번 찍히고(`press` 520ms, 450ms 뒤), 확인 결과가 바뀌면 결과 도장을 다시 찍는다(`stamp` 200ms). 둘 다 `prefers-reduced-motion` 이면 움직이지 않는다.
- 결과 도장은 그림이라 화면 낭독기에서 숨기고(`aria-hidden`), 바뀐 결과는 `#result-status` 한 줄(`aria-live`)로만 읽힌다. 「준비함」 버튼은 누른 뒤에도 같은 버튼에 포커스가 남는다.

## 자기검토 — 아무 개발 도구 랜딩에나 나올 모양인가

- 처음 떠오른 안은 어두운 바탕에 터미널 창, 그라데이션 강조였다. 어느 CLI 소개에나 나오는 모양이라 버렸다. 서식 용지와 도장은 이 주제에서만 나온다.
- 큰 숫자 + 작은 설명 + 그라데이션 띠는 쓰지 않는다. 12종·836칸 같은 숫자는 서식 표 안에서 읽힌다.
- 크림 바탕·테라코타 강조는 피했다. 바탕은 흰 용지, 빨강은 도장에만 쓴다.
- 번호(01·02)는 실제 순서인 설치 단계에만 붙인다. 영문 대문자 라벨, 화살표 붙은 버튼, 가운뎃점으로 이은 메타 줄은 쓰지 않는다.

## 문구 제약

- 서비스 이름·설명에 「노무사」, 「상담·진단·판정·지도·대리·자문」을 쓰지 않는다. 쓰는 말 = 확인·점검·대조·정리.
- 승인 가능성을 점치는 표현을 쓰지 않는다. 「승인」은 「다루지 않는다」는 문맥에서만 쓴다.
- 서식 숫자는 손으로 적지 않는다. `npm run build:web` 이 지도에서 세어 `public/index.html` 에 굽는다(README 표가 0.5.4 에서 낡았던 것을 되풀이하지 않는다). 확인표 선택지 값이 엔진 상수와 어긋나면 `scripts/verify_web_engine.mjs` ⓪ 이 배포를 멈춘다.
- 예외는 「사용 확인」 절 하나다. 거기 숫자는 **판과 날짜를 붙인 실측 기록**이라 손으로 적는다. 근거는 `docs/사용_매뉴얼.md` 8절과 릴리스 커밋 메시지뿐이고, 판이 바뀌면 새 줄을 더하지 옛 줄을 고치지 않는다.
- 「노무사」·「대리」·「자문」 같은 직무 어휘는 쓰지 않는다. 출력물 확인은 「제출 전에 사람이 직접 확인」으로 쓴다.
