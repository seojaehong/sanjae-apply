# 안내 페이지 디자인 (261028)

`https://sanjae-apply.vercel.app/` 의 정본 설계. 화면을 고칠 때 이 문서부터 고친다.

## 누구에게 무엇을

- 읽는 사람: 산재 신청을 준비하는 재해자·가족, 신청을 돕는 사무소 직원, AI 도구에 MCP 를 붙이려는 사람.
- 첫 화면의 일: 급여와 재해 상황을 고르면 **필요한 서식·첨부·근거 조문이 바로 나온다.** 엔진은 npm 패키지와 같은 `src/core` 를 브라우저용으로 묶은 것이다. 입력값은 서버로 가지 않는다.
- 그다음: 내 도구에 연결하는 법 → 채울 수 있는 서식 12종 → 검증 수준 → 이 도구가 하지 않는 일.

## 레퍼런스

design-md 의 `ibm`(Carbon) 을 **구조로만** 빌렸다. 공공·기관 서식 화면에 맞는 이유는 셋이다. 모서리 0px, 그림자 없이 1px 선과 바탕색 차이로 위계를 만든다, 4px 격자. 정체성은 빌리지 않았다. 글꼴(Plex)·고유 파랑(#0f62fe)·밝은 300 굵기 제목은 쓰지 않는다. 근로복지공단의 색·로고도 쓰지 않는다(기관 사칭 금지).

## 개념: 서식 용지

산재 신청은 종이 서식의 일이다. 그래서 페이지 자체를 **신청 전 확인표**라는 서식 한 장으로 만든다.

- 서식의 인쇄된 부분(칸 이름·선)은 먹색, **사람이 채운 값은 볼펜 파랑**으로 쓴다. 엔진이 돌려준 결과도 볼펜 파랑이다.
- 결과 상태는 **인주 도장**으로 찍는다. 「확인할 것이 남음」·「제출할 수 있는 상태」 두 가지뿐이다. 승인 여부는 다루지 않는다.
- 도장이 이 페이지에서 유일하게 대담한 요소다. 나머지는 조용하게 둔다.

- 글꼴: 제목 = **Noto Serif KR 600**(공문서 서식 제목이 명조인 데서 왔다), 본문 = **Pretendard**, 명령어 = 시스템 고정폭.
- 크기: 13 / 15 / 17 / 21 / 28 / 40px. 본문 행간 1.7, 제목 1.3. 한글 자간은 0(제목도 -0.01em 까지만).
- `word-break: keep-all`, 숫자 칸은 `tabular-nums`.
- 모서리 0. 그림자 없음. 서식 외곽만 2px 먹선, 칸은 1px 괘선.

- 왼쪽 정렬, 최대 폭 1120px. 휴대폰에서는 확인표 → 결과 순으로 세로로 쌓는다.
- 움직임은 하나뿐이다. 결과가 바뀌면 도장을 다시 찍는다(180ms). `prefers-reduced-motion` 이면 움직이지 않는다.

## 자기검토 — 아무 개발 도구 랜딩에나 나올 모양인가

- 처음 떠오른 안은 어두운 바탕에 터미널 창, 그라데이션 강조였다. 어느 CLI 소개에나 나오는 모양이라 버렸다. 서식 용지와 도장은 이 주제에서만 나온다.
- 큰 숫자 + 작은 설명 + 그라데이션 띠는 쓰지 않는다. 12종·836칸 같은 숫자는 서식 표 안에서 읽힌다.
- 크림 바탕·테라코타 강조는 피했다. 바탕은 흰 용지, 빨강은 도장에만 쓴다.
- 번호(01·02)는 실제 순서인 설치 단계에만 붙인다. 영문 대문자 라벨, 화살표 붙은 버튼, 가운뎃점으로 이은 메타 줄은 쓰지 않는다.

## 문구 제약

- 서비스 이름·설명에 「노무사」, 「상담·진단·판정·지도·대리·자문」을 쓰지 않는다. 쓰는 말 = 확인·점검·대조·정리.
- 승인 가능성을 점치는 표현을 쓰지 않는다. 「승인」은 「다루지 않는다」는 문맥에서만 쓴다.
- 서식 숫자는 손으로 적지 않고 `public/data/forms.json` 에서 읽는다(README 표가 0.5.4 에서 낡았던 것을 되풀이하지 않는다).
