# 웹편집기 4단계(1차분) 구현·검증

2026-10-31. 기준 master `6a7486c`, 작업 브랜치 `feat/web-editor-phase4-unpaid`(로컬 커밋만).
푸시·PR·운영 병합·배포는 이번 범위에 포함하지 않는다.

## 범위와 결정

칸 입력 화면을 요양급여신청서(`F_YOYANG_APPLY`) 전용에서 서식 id를 받는 구조로 바꾸고, 미지급 보험급여 청구서(`F_UNPAID_CLAIM`, 63칸, 1쪽)를 두 번째 서식으로 붙였다.

미지급 청구서를 고른 까닭: 체크 16칸이 모두 지도 `check_groups`에 묶여 있고, 단일/복수 선택이 3단계에서 승인됐다(수령계좌·확인사항①·행정정보 동의 = 단일, 미지급 급여 종류 10 = 복수). 이번에 추론한 칸은 0이다. 한글 출력·화면 도장·나머지 10종 서식은 다음 단계로 넘긴다.

이번에 정한 것(구현 판단):

- 진입 버튼은 확인표 결과의 서식 행(`fillNote`)에 둔다. 요양과 같은 자리다. 상단 `#try` 고정 버튼은 요양만 둔다.
- 쪽 제목은 서식별 표에 두고, 없으면 「N쪽」으로 쓴다. 미지급은 「1쪽」 하나다.
- 칸 수는 고정값을 쓰지 않는다. catalog(`forms.json`)의 칸 목록과 채우기 지도의 칸 key가 수와 이름 모두 같아야 연다.
- 체크 라벨 끝의 「( )」는 화면 표시에서만 지운다. 지도·`describeForm`·CLI/MCP `slot_labels`는 그대로다.
- 내려받는 파일 이름은 서식 이름을 따른다(`미지급 보험급여 청구서.pdf`).
- 재해발생일 상자는 8칸이다. 화면은 8자리를 넘으면 내려받기를 막는다(3단계와 같이 자르지 않는다). CLI는 12자리를 받으면 앞 8자리를 쓴다. 시험은 화면에 실제로 넣은 8자리 값으로 CLI와 대조했다.

## 실행 경로

`public/index.html` 확인표 → 결과의 `[data-open-editor="<id>"]` 버튼 → `web/main.ts` 지연 import → `openEditor(id)` → `forms.json` 칸 설명과 지도 칸 대조 → 기존 `fillPdf` → PDF.js 미리보기·같은 바이트 내려받기. 닫으면 값·생성 바이트가 사라지는 동작은 바꾸지 않았다.
