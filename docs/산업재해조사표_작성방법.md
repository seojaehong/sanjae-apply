# 산업재해조사표 작성방법

산업재해조사표(산업안전보건법 시행규칙 별지 제30호서식)를 이 도구로 쓰는 방법을 적었다.
확인일은 모두 2026-11-04(KST)다.

> [!IMPORTANT]
> 산업재해조사표는 **고용노동부(관할 지방고용노동관서)** 에 내는 서식이다. 근로복지공단 서식이 아니다.
> 근로복지공단에 요양급여신청서를 냈어도 조사표는 따로 내야 한다.

## 1. 언제·누가·어디에 내나

| 항목 | 내용 | 근거 |
|---|---|---|
| 내는 경우 | 산업재해로 사망자가 생기거나, 3일 이상 휴업이 필요한 부상·질병자가 생긴 경우 | 산업안전보건법 시행규칙 제73조제1항 |
| 내는 사람 | 재해자를 고용한 사업주(파견근로자는 사용사업주의 사업장명을 적는다) | 같은 조, 서식 작성방법 ② |
| 기한 | 산업재해가 발생한 날부터 1개월 이내 | 같은 조 |
| 제출처 | 관할 지방고용노동관서의 장(전자문서 포함) | 같은 조 |
| 근로자대표 확인 | 근로자대표 확인을 받고, 이견이 있으면 그 내용을 첨부한다. 근로자대표가 없으면 재해자 본인 확인 | 같은 조 제3항 |
| 중대재해 | 사망 1명 이상, 3개월 이상 요양 부상자 동시 2명 이상, 부상자·질병자 동시 10명 이상이면 알게 된 즉시 전화·팩스 등으로 따로 보고 | 법 제54조, 시행규칙 제3조·제67조 |
| 기록 보존 | 조사표 사본을 보존하면 산업재해 기록·보존 의무를 갈음한다 | 시행규칙 제72조 |
| 법률 의무 | 산업재해 발생 은폐 금지와 보고 의무 | 법 제57조 |

법령 판: 산업안전보건법 MST 291447, 같은 법 시행규칙 MST 288431(법제처 국가법령정보센터). 조문 원문은 `fixtures/laws/osh_*.xml` 에 받아 두었다.

### 과태료(산업안전보건법 시행령 별표 35, 개정 2026. 7. 28.)

| 위반 | 1차 | 2차 | 3차 이상 |
|---|---|---|---|
| 산업재해 발생 보고를 하지 않음(법 제57조제3항) | 700만원 | 1,000만원 | 1,500만원 |
| 거짓으로 보고함 | 1,500만원 | 1,500만원 | 1,500만원 |
| 중대재해 발생 보고를 하지 않음(법 제54조제2항) | 3,000만원 | | |

- 사업장 밖 교통사고처럼 사업주의 법 위반이 직접 원인이 아닌 것이 명백하면 보고 미이행 과태료에서 빠진다.
- 가중은 최근 5년간 같은 위반으로 처분받은 경우에 적용한다. 중대재해 발생 사업장의 원인조사·감독에서 적발되면 3차 이상 금액을 부과한다.
- 상시근로자 수에 따라 감경 기준(90%·80%·70%)이 있다.

## 3. 도구

| 도구 | 읽기/쓰기 | 하는 일 |
|---|---|---|
| `get_accident_report_guide` | 읽기 전용 | 제출 의무·기한·과태료, 칸별 작성법, 서술 칸 요소·점검표·서식 작성예시, 분류코드 찾는 곳, 자주 틀리는 것, 제출 경로. `workplace_address` 를 주면 관할 찾기 결과를 붙인다 |
| `check_accident_report` | 읽기 전용 | 넣을 값을 점검한다(빈 칸, 하나만 고르는 칸, 날짜·요일, 휴업일수, 원인 4요인, 재발방지 기한·담당, 기한 참고일). 고치지 않는다 |
| `find_labor_office` | 읽기 전용 | 사업장 주소 → 관할 관서·조사표 접수 부서·전화·팩스·출처·확인방법(아래 8절) |
| `fill_form` | 파일 생성 | 정본 서식에 값을 넣어 PDF·hwpx 를 돌려준다. 저장하지 않는다(로컬 `save_to` 를 주면 그 경로에만 쓴다). 결과에 관할 찾기(`labor_office`)를 붙인다 |

도구는 근거·형식·점검·연락처만 준다. 서술 칸의 문장은 호출한 AI 가 사업장이 준 사실로 쓴다.
산업재해 해당 여부나 책임은 판단하지 않는다. 출력에 승인·인정 가능성 표현이 들어가면 서버가 거부한다.

쓰는 순서는 이렇다.

1. `get_accident_report_guide` 로 칸별 작성법과 서술 칸 요소를 받는다.
2. 사업장 자료로 값을 채운다. 서술 칸은 요소·점검표에 맞춰 쓴다.
3. `check_accident_report` 로 점검하고 error 를 고친다.
4. `find_labor_office` 로 제출 관서와 접수 부서를 확인한다.
5. `fill_form(form_id='F_INDUSTRIAL_ACCIDENT_REPORT')` 로 파일을 만든다.
6. 사업주 서명·날인과 근로자대표(또는 재해자) 확인을 받아 낸다.

## 4. 칸별 작성법

칸 이름은 `fill_form` 의 values 이름이다. 서식 뒤쪽 「작성방법」을 줄여 옮겼다.

| 칸 | 작성법 |
|---|---|
| `workplace_no` · `biz_reg_no` | 산재관리번호(일괄적용이면 사업개시번호도)와 사업자등록번호. 산재보험 미가입이면 사업자등록번호만 |
| `employer_name` | 재해자가 근로계약을 맺고 급여를 받는 사업장명. 파견근로자는 사용사업주, 건설 하수급 소속이면 하수급 사업장명 |
| `worker_count` | 최근 근로자 수(정규직·일용직·임시직·훈련생 포함) |
| `workplace_address` | 사업장 소재지. 관할 관서를 정하는 값이다 |
| `industry` | 한국표준산업분류 세세분류 5자리. 모르면 업종명과 주요 생산품 |
| `prime_contractor_*` | 사내 수급인 소속일 때(건설업 제외) 원도급인 사업장명과 번호 |
| `dispatch_employer_*` | 파견근로자일 때 파견사업주 사업장명과 번호 |
| 건설업 칸(`orderer_*` · `main_contractor_*` · `site_name` · `construction_type` · `progress_rate` · `construction_amount`) | 건설업만. 공사 현황은 원수급 사업장 기준, 공정률은 전체 공정률, 공사금액은 백만원 단위 숫자 |
| `name` · `rrn7` · `address` · `mobile` | 재해자 성명, 주민등록번호 앞 7자리(서식이 앞 7자리만 받는다), 주소, 휴대전화 |
| `nationality_*` · `nationality` · `visa_status` | 외국인이면 국적과 체류자격 기호(예: E-9) |
| `job` | 한국표준직업분류 세세분류 5자리. 모르면 직업명과 주요 업무 |
| `hire_*` | 이 사업장 입사일 |
| `same_job_*` | 같은 종류 업무 근속기간. 다른 회사의 같은 업무 경력까지 합산 |
| `employment_*` | 하나만 고른다(상용·임시·일용·무급가족종사자·자영업자·그 밖의 사항) |
| `shift_*` | 하나만 고른다(정상·2교대·3교대·4교대·시간제·그 밖의 사항) |
| `injury_type` · `injury_part` | 상해종류와 부위. 둘 이상이면 심한 것부터 |
| `lost_days` · `death` | 휴업예상일수는 재해 당일을 빼고 센다. 사망이면 사망 칸 |
| `accident_*` | 발생일시(년·월·일·요일·시(24시)·분) |
| `accident_place` · `work_type` · `accident_situation` | 재해발생 개요(5절) |
| `accident_cause` | 재해발생 원인(5절) |
| `prevention_plan` | 재발방지 계획(5절) |
| `tech_support_request` | 한국산업안전보건공단 무료 기술지원을 받으려면 표시 |
| `comwel_guide_consent` | 근로복지공단이 재해자에게 산재보험급여 신청방법을 안내하는 데 동의하는 경우만(재해자 의사에 따른다) |
| `writer_*` · `apply_*` · `owner_name` · `worker_rep_name` | 작성자·작성일, 사업주, 근로자대표(없으면 재해자) |
| `labor_office` | 「(  )지방고용노동청장(지청장) 귀하」 괄호 값. `find_labor_office` 의 `labor_office_value` 가 제안 값이다(8절) |

## 5. 서술 칸

### 재해발생 개요(`accident_place` · `work_type` · `accident_situation`)

들어갈 요소는 발생일시, 발생장소(공정까지), 작업유형(누가 · 어떤 기계·설비로 · 무슨 작업 중), 당시 상황(불안전한 상태와 불안전한 행동)이다.

점검표:

- 문장마다 주어(재해자·동료)가 분명한가
- 설비 이름·번호와 공정이 장소·작업유형 칸과 같은가
- 상태(무엇이 어떤 상태였나)와 행동(누가 무엇을 했나)이 둘 다 있는가
- 결과(어디를 어떻게 다쳤나)가 상해종류·부위 칸과 맞는가
- 확인되지 않은 것을 사실처럼 쓰지 않았는가(「확인 중」으로 적는다)

서식 뒤쪽 작성예시: 「사출성형부 플라스틱 용기 생산 1팀 사출공정에서 재해자 000가 사출성형기 2호기에서 플라스틱 용기를 꺼낸 후 금형을 점검하던 중, 재해자가 점검중임을 모르던 동료 근로자 000가 조작 스위치를 가동하여 금형 사이에 재해자가 끼어 사망하였음」.

### 재해발생 원인(`accident_cause`)

네 요인으로 나누어 적는다(서식 작성방법).

| 요인 | 예 |
|---|---|
| 인적 요인 | 무의식 행동, 착오, 피로, 연령, 커뮤니케이션 등 |
| 설비적 요인 | 설계상 결함, 방호장치 불량, 작업표준화 부족, 점검·정비 부족 등 |
| 작업ㆍ환경적 요인 | 작업정보 부적절, 작업자세·동작 결함, 작업방법 부적절, 작업환경 불량 등 |
| 관리적 요인 | 관리조직 결함, 규정·매뉴얼 불비, 안전교육 부족, 지도감독 부족 등 |

「부주의」 한 단어로 끝내지 않는다. 그 행동을 가능하게 한 설비·작업방법·관리의 빈틈을 적는다.

### 재발방지 계획(`prevention_plan`)

- 원인 칸의 요인마다 대응 조치를 하나 이상 적는다.
- 조치마다 무엇을 · 언제까지 · 누가(부서·직책) 하는지 적는다.
- 같은 설비·공정의 다른 기계·작업장까지 범위를 적는다.
- 교육만 적지 않고 설비 개선·작업 절차(전원 차단·잠금·표지 등)를 함께 적는다.
- 이행 확인 방법(점검표, 산업안전보건위원회 보고 등)을 적는다.

지침 도구에 합성 예시가 있다. 실제 사업장 사실로 바꿔 쓴다.

### 칸이 모자랄 때(별지)

PDF 의 서술 칸은 한두 줄이다. 넘치면 칸에 「(별지에 적음)」을 쓰고 문서 끝에 별지 쪽을 붙여 전문을 적는다.
한글(hwpx)도 글자를 7pt 까지 줄여도 넘치면 같은 방식으로 적는다. 결과의 `report.annexed` 에 별지로 옮긴 칸이 나온다.

## 8. 제출 경로와 관할 관서 찾기

### 제출 경로

- 관할 지방고용노동관서에 방문·우편·팩스로 낸다.
- 온라인: 고용노동부 노동포털 민원신청 「산업재해조사표」(민원코드 AH038). 사업주 기업회원 로그인이 필요하다.
  `https://labor.moel.go.kr/minwonApply/minwonFormat.do?searchVal=AH038&searchGubun=1&searchRlm=2`
- 이 도구는 팩스를 보내지 않는다. 번호 안내까지다.

### 관할 찾기(`find_labor_office`)

사업장 주소를 넣으면 관할 관서와 조사표 접수 부서를 돌려준다.

| 항목 | 내용 |
|---|---|
| 관할 근거 | 「고용노동부와 그 소속기관 직제 시행규칙」 별표 1(관할 구역) <개정 2026. 6. 30.>, 2026-07-01 시행 · 별표 3(상위청) |
| 연락처 근거 | 각 관서 고용노동부 누리집 부서 안내 화면 |
| 데이터 | `data/labor-offices/` (관서 49곳, 부서 111행). 원본은 별도 작업 `labor-office-directory`, 확인일 2026-11-04. 자세한 것은 그 폴더 README |
| 찾기 로직 | `src/accident/jurisdiction.ts` — 원본 `find.mjs` 를 TypeScript 로 옮겼다. 원본 시험 15건과 같은 사례를 `test/labor-office.test.ts` 가 본다 |

결과(`status`):

| 값 | 뜻 |
|---|---|
| `CONFIRMED` | 관서 하나로 정해졌다(`office`) |
| `CANDIDATES` | 시도가 빠져 같은 이름 시군구가 여럿이거나(중구·고성군 등), 법령이 읍·리 단위로 나누는 곳(칠곡군 석적읍)인데 주소에 그 단위가 없다. 후보(`candidates`)를 주고 하나로 정하지 않는다 |
| `NOT_FOUND` | 시도·시군구를 읽지 못했다. 노동포털·누리집 찾는 길(`fallback`)을 준다 |
| `DATA_NOT_CONNECTED` | 데이터 파일이 없다(배포 오류일 때만) |

관서마다 돌려주는 칸:

| 칸 | 내용 |
|---|---|
| `office_name` · `office_kind` · `parent_name` | 관서 이름, 지방청/지청/출장소, 상위 지방청 |
| `office_address` · `main_phone` · `main_fax` | 관서 주소·대표번호(대표팩스는 대부분 화면에 없다) |
| `report_to` | 조사표 접수 부서(기본): 부서 이름, 전화, 팩스, 부서 주소, 확인방법(`phone_verification` · `fax_verification`), 팩스 출처(`fax_source`), 화면 주소(`source_url`), 주의(`notes`) |
| `report_to_alt` | 지방청 직할 구역일 때만: 광역산재예방감독과(보조) |
| `confirm_before_submit` | 「제출 전 전화 확인 권장」 — 접수 과 미확정·단일 출처 팩스·번호 미확인일 때 붙는다 |
| `cautions` | 왜 전화 확인을 권하는지 등 |
| `labor_office_value` | 서식 괄호 값 제안. 지방청은 「서울」, 지청은 「서울강남」처럼 앞부분. 출장소는 제안하지 않는다. 칸에 자동으로 넣지 않는다 |

확인방법 값: 공식 직접 확인(관서 화면에서 직접 읽음) · 두 리서치 일치 · 단일 출처 · 미확인.

주의:

- **지방청 7곳(서울·경기·중부·부산·대구·광주·대전) 직할 구역**은 조사표 접수 과가 확정되지 않았다. 직제 시행규칙은 「사업장의 재해발생 상황파악, 원인조사 및 조치」를 광역산재예방감독과장 분장으로 두고, 2025-09 전자팩스번호표의 옛 산재예방지도과 팩스는 5곳(서울·경기·중부·대구·광주)에서 지금 산재예방감독과 팩스와 같다. 그래서 산재예방감독과를 기본, 광역산재예방감독과를 보조로 두 번호를 함께 내고 「제출 전 전화 확인 권장」을 붙인다. 광주청 광역산재예방감독과는 화면에 번호가 없어 미확인이다.
- **여수지청** 산재예방감독과 팩스는 관서 화면 팩스 칸이 비어 있어 2025-09 부서별 전자팩스번호표 값을 쓴다. 확인방법이 「단일 출처」로 나오고 「제출 전 전화 확인 권장」이 붙는다.
- **제주** 사업장은 광주지방고용노동청 관할이고, 연락처는 제주 합동청사의 제주산재예방감독팀이다.
- **건설업**: 조사표 값에 건설업 칸(`construction_*`)이 있거나 `construction=true` 면, 건설산재예방감독과가 있는 관서(20곳)는 그 과를 돌려준다. 없는 관서는 산재예방감독과를 돌려주고 그 사실을 적는다.
- 옛 이름 주소도 읽는다(광주광역시·전라남도 → 전남광주통합특별시, 전라북도 → 전북특별자치도, 강원도 → 강원특별자치도, 경상북도 군위군 → 대구광역시, 인천 중구·동구 → 제물포구 등).
- 데이터에 직원 성명은 없다. 도구도 부서·번호·주소·출처만 낸다.
- 번호는 확인일(2026-11-04) 기준이다. 관서 이전·조직 개편으로 바뀔 수 있다.

## 9. 기한 참고일

`check_accident_report` 는 발생일부터 1개월이 되는 날을 참고일로 준다(민법 제157조 초일 불산입, 제160조 월 단위 계산, 그달에 같은 날이 없으면 말일).
참고일이 토·일이면 민법 제161조로 다음 날이 되지만, 공휴일은 계산하지 않는다. 참고일이 지났으면 시행규칙 제73조제2항 특례(자진 제출 등)와 그 적용 제외를 안내한다.

## 10. 도장

도장 기본 자리는 사업주(`applicant`) 하나다. 근로자대표 확인란(`worker_rep`)은 근로자대표 본인 도장만 `spot='worker_rep'` 로 따로 찍는다.

## 11. 시험

- 값은 전부 합성값(홍길동 등)이다. 실제 재해자 정보는 쓰지 않는다.
- `test/accident.test.ts`: 지침·점검·별지·도장.
- `test/labor-office.test.ts`: 관할 찾기(원본 시험 15건과 같은 사례 + 데이터 확인 1건 + 도구 출력 8건). 같은 이름 구·세종·제주·영월·칠곡·옛 이름·건설업·후보·none, 지방청 두 번호와 표시, 여수 단일 출처, 관할표 전 구역에서 금지어·절대 경로·직함 뒤 이름 모양이 없는지.
- `test/mcp.test.ts`·`test/stdio.test.ts`: 도구 8개, 읽기 전용 표시, `fill_form` 결과의 `labor_office`.
