# 웹편집기 3단계 구현·검증

2026-10-30. 기준 master `7233f6e`, 작업 브랜치 `feat/web-editor-phase3`.
운영 병합·배포는 이번 범위에 포함하지 않는다.

## 범위와 결정

사용자 승인: “근로자유형·각 예/아니오 묶음은 단일선택, 미지급 보험급여 종류처럼 동시 해당 가능한 묶음은 복수선택”.

요양 원본 1·2쪽과 미지급 급여 원본 1쪽을 렌더해 확인했다. 요양 지도에는 12개 단일선택 묶음을 명시한다. 미지급 지도에는 급여 종류의 복수선택과 계좌·확인·동의의 단일선택을 명시한다. 원본 묶음과 label의 콜론 앞말은 같지 않을 수 있으므로 `group`으로 배타성을 추론하지 않는다. 나머지 서식의 화면·한글 출력·도장 UI는 다음 단계다.

## 실행 경로와 상태

`public/index.html`·확인표 결과 → `web/main.ts`의 지연 import → `web/editor.ts` → `forms.json`의 공용 칸 설명 → 기존 `fillPdf` → PDF.js canvas·같은 생성 바이트의 PDF 내려받기.

| 화면 상태 | 의미 | 내려받기 |
|---|---|---|
| 준비·갱신 중 | 현재 입력의 PDF 생성·렌더가 끝나지 않음 | 차단 |
| 숫자 칸 오류 | 숫자 이외 입력 또는 지도 자리 수 초과 | 차단, 자르지 않음 |
| 미리보기 갱신 | 현재 입력과 같은 PDF가 생성·렌더됨 | 허용 |
| 실패 | 원본 로딩 또는 생성·렌더 실패 | 차단, 값 보존 후 재시도 |
| 닫음 | 값·생성 바이트·문서·이벤트 해제 | 불가 |

‘미리보기 갱신’은 제출 요건이나 내용의 타당성 확인을 의미하지 않는다. 입력 변경 직후 이전 PDF는 내려받을 수 없으며, 오래된 비동기 결과는 revision으로 버린다. 모든 동의는 미선택 상태에서 시작하고 선택을 지울 수 있다.

## 재현

웹 개발·빌드는 Node 22.13 이상 또는 24에서 `npm.cmd ci`, `npm.cmd test`. 브라우저 UI 시험만 실행하려면 빌드 후 `node scripts/verify_web_editor.mjs`. `EVIDENCE_DIR`를 지정하면 합성 PDF와 화면을 해당 경로에 남긴다. 생성 자산·실행 로그·합성 PDF는 커밋하지 않는다.

참고: [PDF.js 렌더 예제](https://mozilla.github.io/pdf.js/examples/), [CSP Report-Only](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy-Report-Only), [Pretendard 라이선스 원문](https://raw.githubusercontent.com/orioncactus/pretendard/v1.3.9/LICENSE). UI 글꼴은 버전이 고정된 개발 의존성에서 복사하고 라이선스를 함께 제공한다.
